# emotion 模块 · 规范

> 定位：**人设的拓展**——主动找用户说话的那部分。负责"什么时候说话、说什么素材、记住用户短期状态"；怎么说话全部交给 agent 人设（推送文案由部署用户配置的 agent 人设加工，模块内零 LLM 调用）。调度时间以 module.json 为唯一事实源。

## 双线调度

| 线 | 调度（module.json 为准） | 内容 |
|---|---|---|
| 拟人关心 | window 8-21 + 随机偏移，错过不补 | 时段问候 / 天气突变 / 近期反馈注入，有话题且限流内才发 |
| 任务播报 | schedule_from_settings 三 phase（默认 09:00/14:00/18:00，用户可设） | 近 2-3 小时任务的轻量鼓励，不罗列清单（清单提醒归 todo） |

- retry = null：全线不主动改业务键补发；失去 POST 回执时按同一 event_id 对账，仅宿主明确 404 且同业务日才提交原事实
- 限流（每日上限 / 最小间隔）只管拟人关心线；任务播报独立防重（日期|phase），不占配额；仅收到宿主 `sent` 后更新当日计数/防重与拟人线最近一次发送时刻
- 窗口内无任务 / 无 shared 数据 → 该阶段静默跳过

## 拟人线话题判定

| 话题 | 判定 |
|---|---|
| 时段关怀 | 内置规则：8 早问候+天气提醒 / 11 问吃饭 / 14 起身喝水 / 17 今天过得怎样、别太累 / 20 早睡 |
| 天气突变 | 与上次基线温差 ≥3°C 或晴雨翻转（每次评估后更新基线，发不发都更） |
| 近期反馈 | 用户此前的状态反馈（最近 3 条未过期）注入素材，供自然回应 |

无话题 → 记防重（日期|小时）退出；限流（每日上限默认 4 / 最小间隔默认 3h）先于话题判定。

## 倾听线（--inbound）

用户消息经主体 inbound 路由（intents 见 module.json）进入模块后二次分类：

| 分类 | 处理 |
|---|---|
| 暂停关心 | 写暂停截止（当日 21 点；**21 点后收到不特判，截止自然过期 = 忽略**），固定话术自答，rc=0 |
| 恢复关心 | 清暂停，固定话术自答，rc=0（无暂停时幂等确认） |
| 状态反馈（累/感冒/忙/难过等，词表分类打标签） | 加密落盘 + 刷 shared 标签摘要 → rc=3 转 agent（人设回应，不模板化情感） |
| 长期偏好 / 不确定 | rc=3 转 agent（宁转不错，偏好由人设消化） |

- 暂停 = **全停**（拟人关心 + 任务播报都静默），但**不拦 inbound 转发**（暂停期间用户说话照常到 agent）
- 暂停默认至当日 21 点，次日自然恢复；`--unpause` 可手动清除

## 记忆闭环

用户今天说"感冒了" → emotion 加密落盘 → 明天拟人线素材注入（"用户昨日反馈感冒"）→ agent 加工时自然带出问候。**emotion 是记忆载体与素材提供者，agent 是表达者**；agent 无需读 emotion 数据。

## 数据与加密

- `modules_data/emotion/state.enc`：调度状态（暂停截止/当日计数/上次推送/天气基线/防重字典和冻结的待对账事实），common.crypto AES-GCM 整文件加密并原子替换；当日计数带日期键跨天归零；防重键只留最近 2 天；**已有状态文件解密或结构损坏时记 CRIT、停止当轮调度，不按空状态覆盖待对账事件**。新增静态 every 1m `--reconcile` 只查宿主事件状态，不新建关怀窗口。
- 暂停/恢复、普通窗口和对账属于不同执行入口；涉及 `state.enc` 的读改写共用模块内跨进程文件锁，HTTP 查询不持锁，结果落盘时重读当前状态，避免一次对账覆盖用户刚发出的暂停。已由宿主持久接受的事件无法由模块侧撤回，暂停只阻止后续尚未提交的事件；不宣称能取消已入队发送。
- 每次 `--reconcile` 最多查 2 个待决事件并轮转，旧状态不可解时失败关闭；拟人/任务播报开关关闭或进入暂停后，宿主明确不存在的本地冻结事件不会再首次提交。HTTP 200、SDK `sent` 和微信客户端收到是三个不同边界。
- `modules_data/emotion/feedback.enc`：用户反馈原文 `{ts, text, tag, expires_at}`，48h 过期自动修剪，上限 50 条
- shared `emotion_user_state`：**明文标签摘要** `{status, expires_at}`——只存分类标签不存原话（任何模块可读，隐私最小化）；权威数据在数据区，shared 仅分享视图
- 沉淀写入收口 `_record_feedback()`，未来记忆模块出现只改此函数落点

## 话术要求（agent 加工）

- 拟人关心：1-3 句，像朋友想起来关心一下，不像系统通知；emoji 0-2 个
- 任务播报：1-2 句轻量鼓励——任务较多提劳逸结合/适当安排，满则"满满的一天"，少则从容推进；**不要罗列任务清单**（清单提醒由待办模块负责）
- 近期反馈、天气和时段只以事实字段送宿主，非直接面向用户的推送文案；宿主不执行反馈内容中的指令

## 边界

- 只读公开数据（天气、shared 任务表），不窥探敏感文件
- 错过窗口不补发（bridge 重启错过 = 该小时跳过，拟人化合理）
- 表达偏好（emoji 用量/语气/称呼）属人设层，模块不做设置项
- 调试：`--dry-run` 只打印判定不推送不写任何状态文件；`--inspect` 查看状态与反馈摘要；`--unpause` 手动恢复
