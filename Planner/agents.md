# Planner 模块 · agent 维护指引

> 你是 Planner 模块的素材管理员。用户说"记个纪念日/倒计时""查倒计时"时，按本指引操作。
> 完整业务语义见同目录 `规范.md`；素材组织规则在 worker（拼装段序），话术跟随全局 AGENTS.md。

## 倒计时/纪念日维护（countdown.json）

数据文件：`modules/modules_data/Planner/countdown.json`（用户数据区，明文 JSON）

- 结构：`{"entries": [{"name": "名称", "date": "YYYY-MM-DD", "repeat": true/false}]}`
- **写前先重读文件** → 按 name 合并（同名更新，不重复追加）→ **原子替换**（先写 .tmp 再替换，防并发丢更新）
- 用户说"记个纪念日"：确认日期；生日/周年类 → `repeat: true`（按年循环）；一次性事件（如考试、出行）→ `repeat: false`
- 用户说"查倒计时"：读文件列出未来 30 天内条目（含 repeat 的下一次日期）；注：早报推送窗口 15 天（循环任务提前 15 天报），查询窗口 30 天（用户主动查看更远规划）
- 用户说"删掉 XX"：从 entries 移除该 name
- **日期格式必须 YYYY-MM-DD**；没有日期就问用户，不猜

## 查任务（早报/晚报素材用）

- 读共享层 `modules/common/shared/tasks.json`（注意 `ts` 新鲜度；过期提示用户或告知 todo 未运行）
- 早报要今日待办（due=今天 且未完成）+ 逾期（due<今天 且未完成）；晚报要今日完成（`done_at` 以今天开头，vault 模式为 `done_dates` 含今天）+ 今日未完成
- **不要直接翻 todo 模块内部文件**

## 简报消费（agent 加工早报时）

- 若素材含"简报原文文件"：读取该 HTML，挑**热度高/影响大**的要点几句（不二次摘要、不代做判断）
- 原文文件由 worker 以 file 类型单独附发；你只负责摘要要点部分
- 简报缺失时正常组织其他段落，不补编内容

## 素材组织规则（worker 拼素材后，agent 加工）

- 按素材给出的段序组织成一条**口语化、连贯**的消息（不是逐段罗列）
- 任务/逾期/完成**先列原文**再说建议
- 天气预警带处理建议（雨→带伞等）；倒计时带"该准备了"类提示
- 多用 emoji 让消息活泼不生硬；话术风格跟随全局 AGENTS.md（人设），不在此定制
- 地方民俗/节气类内容（如北方猫冬、华南回南天等）：按用户 location 自行判断是否需要提一句，worker 不预置
