# Planner 模块 · 规范

> 职责：早晚报聚合模块（晨间早报 + 晚间复盘）。聚合型：
> worker 拼**信息条目稿**（零指令：事实/要点/信息性短语） → post_push(reminder) → push_render
> 单轮渲染（tier 人设语气润色，禁工具、不增不漏） → 用户。agents.md 只服务入站交互，不在推送链路上。
> 调度：bridge scheduler 按 module.json 的 schedule（由 schedule_from_settings 联动生成）spawn，
> `--phase morning|evening` 区分阶段，跑完即止。

## 数据依赖（全部由数据可得性决定，非设置项）

| 段 | 来源 | 规则 |
|---|---|---|
| 任务（待办/完成/逾期） | todo 的 `shared/tasks.json` | **读到就读，读不到就没有**（planner 是消费者，任务数据归属 todo） |
| 节假日/农历 | common.calendar / holidays | 同上 |
| 天气 + 气象预警 | common.weather | location 驱动；预警（暴雨/雷暴/大雪等）同源 |
| 花粉/台风 | common.localdata | location 符合 → 拉取 → 进 shared（客观数据）；开关 + 位置显隐 |
| 倒计时/纪念日 | `modules_data/Planner/countdown.json` | planner 自己生产，agent 维护；有条目才有段 |
| 简报 | `modules_data/Planner/briefing/`（HTML 原文） | 开关 + 有产物才段 |

## 晨间早报（单条消息 + 简报原文双发）

- **时序**：module.json cron（morning_time）触发 spawn；素材拼装本地完成（读 shared/缓存天气），失败 rc=1 由 scheduler 按 retry 补发。
- **简报未就绪兜底**（briefing_on 且当天无 `YYYY-MM-DD.html`）：按 `bridge.jobs.job_registered` 三态分流——
  任务未登记/诊断异常 → 照发早报并在素材标注原因；任务已登记 → rc=1 等待（retry 补发轮询，次数上限 = 部署 retry.max，与推送失败共享预算），超次后保底发无简报早报（带标注）。等待期用户零感知。
- **段序**（信息条目稿，逐段成品；渲染层只润色语气，不改信息）：
  1. 问候 + 历法：`{称呼}，早上好呀！今天是 M 月 D 日，星期X`（称呼读 `.config/agent/identity.json` 的 address，未配置退化"早上好呀！"；农历/节气/法定节假日/三伏/数九有则并入此行）
  2. 天气 + 气象预警（预警带处理建议，如雨→带伞、雷暴→减少外出；预警无则略）
  3. 温差提醒（快照可得且当前与未来数小时温差 ≥8°C：`今日温差较大（{min}~{max}°C），注意增减衣物。`；无则略）
  4. 倒计时/纪念日（当天 `今天是X的时候了`；未到 `X还有 N 天，该准备了`；repeat 距下一次 ≤15 天开始报；一次性创建即报）
  5. **逾期**（提前，催处理，一条不漏，行内带到期日）
  6. 今日待办（`今天有 N 件事：` + 原文行；无则 `今天没有明确截止的待办。`；shared 超 25h 未刷追加数据未更新提示）
  7. 简报要点（briefing_on 且当天有 HTML：`summary.txt` 要点全文 + 原文 file 附发；summary 缺失降级一句话；无产物走未就绪兜底）
  8. 收尾提示（**末行**，`收尾提示：<方向>`；worker 规则化选方向——逾期 > 倒计时当天 > 温差，命中才拼；渲染层按其方向结合素材生成一句自然收尾，不播报该行）
- 素材**零指令**（除收尾提示行的受控方向句外，无任何加工指令；鼓励/语气收尾由渲染层按收尾提示生成）。
- 防重：morning_sent.json（key=日期；`<date>|briefing` 标记简报已随早报送达，供晚报兜底判定；`<date>|attempt` 为简报等待计数）。

## 晚间复盘（单条消息）

- **段序**（信息条目稿）：`{称呼}，晚上好呀！` → 今日完成（`今天完成 N 件：` + 原文）→ 今日未完成/逾期（`还有 N 件今日任务未完成：` + 原文）→ 倒计时 → 简报兜底段（见上）→ 晚间建议（`EVENING_TIPS` 池按年积日轮换一条，通用化）→ 收尾提示（末行，按完成情况选方向：未完成温和提醒 / 全完成肯定 / 无任务关照休息）。
- **简报兜底**：早报没带成简报（MORNING_SENT 无 `<date>|briefing` 标记）且当天简报已生成 → 晚报补简报段 + 原件附发（简报最晚当天送达，不静默丢失）。
- 防重：evening_sent.json（key=日期）。

## 倒计时/纪念日（countdown.json）

- 结构：`{"entries": [{"name", "date", "repeat": bool}]}`（date = YYYY-MM-DD）
- repeat（生日/纪念日，按年循环）：距下一次 ≤15 天开始报，到期报"就是今天"；过期进入下一年循环
- 一次性：创建即报；过期停报；**超时 15 天自动删除**（worker 运行时清理）

## 信息简报块

- 产出：HTML 原文 → `modules_data/Planner/briefing/YYYY-MM-DD.html`（**私有，不进 shared**；外部信息，助理不代做判断）
- 时序：`morning_time - 5min` 生产（job.template.json + register 联动 opencode scheduler 自动登记）
- 早报消费：按**当天日期文件名精确匹配**（不取目录最新，防跨天误用旧产物）；有产物 → 读同名 `YYYY-MM-DD.summary.txt` 要点全文进素材（summary 由简报生成任务随 HTML 产出，缺失降级一句话）+ 原文 file 附发（file 失败重试 3 次，仍失败 → 早报补一句说明 + 不记已发）；无产物 → 未就绪兜底（见晨间早报节）
- 方向：预设 6 方向（directions.json 只读，明文供 web 候选）+ 自定义（`modules_data/Planner/prompts/custom/` 明文，web 导入/删除；勾选后其 prompt 文本并入简报生成指示，置于基底之后）
- 基底 prompt：预设（明文 `prompts/base.prompt.md`，sha256 完整性校验兜底，无需加密）；job 登记联动：简报 job 受任务级开关 `briefing_on`（job.template.json `enabled_field`，关闭即注销）与 phase 级 `planner_on` 双重 AND 判定
- 清理策略：简报数 > 5 → 每 5 天清最旧 5 个；≤ 5 → 清 3 天前；≤ 3 → 不清理

## 边界

- 逾期推送只在此模块（todo 模块不管逾期）
- 任务数据缺失（todo 未运行/未装）→ 待办/逾期/完成段自动无段，不报错
- 简报文件缺失 → 走未就绪兜底（见晨间早报节）：任务已登记等 retry 超次保底，未登记/诊断异常标注照发
- 话术风格跟随全局人设（部署态 instructions 指引）；本模块 agents.md 只写素材组织规则，不独立定制话术
