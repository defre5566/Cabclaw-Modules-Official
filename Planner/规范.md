# Planner 模块 · 规范

> 职责：早晚报聚合模块（晨间早报 + 晚间复盘）。聚合型：
> worker 汇总**结构化事实**（分区/任务/天气/历法/简报引用）→ post_push(reminder) → bridge 读取当前部署人设无工具单轮表达 → SDK 发送文字；依赖文件只在文字 `sent` 后发送。agents.md 只服务入站交互，不在推送链路上。
> 调度：bridge scheduler 按 module.json 的 schedule（由 schedule_from_settings 联动生成）spawn，
> `--phase morning|evening` 区分阶段，跑完即止。

## 数据依赖（全部由数据可得性决定，非设置项）

| 段 | 来源 | 规则 |
|---|---|---|
| 任务（待办/完成/逾期） | todo 的 `shared/tasks.json` | **读到就读，读不到就没有**（planner 是消费者，任务数据归属 todo） |
| 节假日/农历 | common.calendar / holidays | 同上 |
| 天气 + 气象预警 | common.weather | location 驱动；预警（暴雨/雷暴/大雪等）同源 |
| 花粉/台风 | common.localdata | location 符合 → 拉取 → 进 shared（客观数据）；开关 + 位置显隐 |
| 倒计时/纪念日 | `modules_data/Planner/countdown.json` | planner 自己生产，agent 维护；有条目才有段 |
| 简报 | `modules_data/Planner/briefing/`（HTML 原文） | 开关 + 有产物才段 |

## 晨间早报（单条消息 + 简报原文双发）

- **时序**：module.json cron（morning_time）触发 spawn；素材拼装本地完成（读 shared/缓存天气），失败 rc=1 由 scheduler 按 retry 补发。
- **简报未就绪兜底**（briefing_on 且当天无 `YYYY-MM-DD.html`）：按 `bridge.jobs.job_registered` 三态分流——
  任务未登记/诊断异常 → 照发早报并在素材标注原因；任务已登记 → rc=1 等待（retry 补发轮询，次数上限 = 部署 retry.max，与推送失败共享预算），超次后保底发无简报早报（带标注）。等待期用户零感知。
- **事实分区**（早报/日历/天气/任务/简报状态，供宿主组织段落；`--dry-run` 的旧素材打印仅便于定位数据）：
  - 段1 开场：问候历法（`{称呼}，早上好呀！今天是 M 月 D 日，星期X`，称呼读 `.config/agent/identity.json` 的 address，未配置退化"早上好呀！"；农历/节气/法定节假日/三伏/数九并入）→ 天气 + 预警（带处理建议）→ 温差提醒（≥8°C）→ 倒计时（当天 `今天是X的时候了`；未到 `X还有 N 天，该准备了`）
  - 段2 任务：**逾期**（提前，催处理，行内带到期日）→ 今日待办（`今天有 N 件事：` + 原文；shared 超 25h 未刷追加数据未更新提示）
  - 简报：briefing_on 且当天有 HTML → `context.html_path` 引用当日文件，宿主只抽取标题、正文和 HTTPS 来源作事实摘要，不让模型读原始路径；无产物走未就绪兜底
  - 段4 收尾：收尾提示（**末行**，`收尾提示：<方向>`；worker 规则化选方向——逾期 > 倒计时当天 > 温差，命中才拼；渲染层按其方向结合素材生成一句自然收尾，不播报该行）
- 配置异常提示独立首段（settings.json 损坏时）。
- 防重：`push_events.json` 先原子保存日期+phase 的文字/附件事件键与事实，再 POST；每分钟 `--reconcile` 只读宿主事件状态。`morning_sent.json` 的日期仅在文字 `sent` 时写入；`<date>|briefing` 仅在附件 `sent` 时写入，供晚报兜底判定；`<date>|attempt` 为简报未就绪等待次数。`sent` 不宣称微信端实际送达。
- 对账每分钟至多扫描 2 个待决业务 slot（各含文字与可选文件）；游标轮转处理积压，数据区已记录文字 `sent` 时，即使宿主后续查询不到事件也不自动重发文字或重建附件依赖。总开关/晚报开关关闭后不首次提交尚未接受的事件，已接受的事件仍据宿主状态对账。

## 晚间复盘（单条消息）

- **段序**（信息条目稿，自然段分组）：段1 问候（`{称呼}，晚上好呀！`）→ 段2 任务：今日完成（`今天完成 N 件：` + 原文）+ 今日未完成/逾期（`还有 N 件今日任务未完成：` + 原文）+ 倒计时 → 段3 简报兜底段（见上）→ 段4 收尾：晚间建议（`EVENING_TIPS` 池按年积日轮换一条，通用化）+ 收尾提示（末行，按完成情况选方向：未完成温和提醒 / 全完成肯定 / 无任务关照休息）。
- **简报兜底**：早报未关联当天简报且今日生成后 → 晚报附简报；如果早报已接受过同一文件事件（即使文件仍 pending、failed 或 unknown），晚报不另建文件键重发。
- 防重：`evening_sent.json` 日期只在文字事件 `sent` 时记录，文字与文件分别记账；`failed/unknown` 不换键自动补发。

## 倒计时/纪念日（countdown.json）

- 结构：`{"entries": [{"name", "date", "repeat": bool}]}`（date = YYYY-MM-DD）
- repeat（生日/纪念日，按年循环）：距下一次 ≤15 天开始报，到期报"就是今天"；过期进入下一年循环
- 一次性：创建即报；过期停报；**超时 15 天自动删除**（worker 运行时清理）

## 信息简报块

- 产出：HTML 原文 → `modules_data/Planner/briefing/YYYY-MM-DD.html`（**私有，不进 shared**；外部信息，助理不代做判断）
- 时序：`morning_time - 5min` 生产（`job.template.json` + register 联动 bridge scheduler 自动登记）
- 早报消费：按**当天日期文件名精确匹配**（不取目录最新，防跨天误用旧产物）；有产物 → 传日期与文件引用供宿主受限提取 1–2 条要点，原文 file 用 `after_event_id` 依赖文字事件；文字/文件各自查状态。文件 `failed/unknown` 不改键自动重发或发未经确认的“失败说明”提醒。无产物走未就绪兜底（见晨间早报节）。
- 方向：预设 6 方向（directions.json 只读，明文供 web 候选）+ 自定义（`modules_data/Planner/prompts/custom/` 明文，web 导入/删除；勾选后其 prompt 文本并入简报生成指示，置于基底之后）
- 基底 prompt：预设（明文 `prompts/base.prompt.md`，sha256 完整性校验兜底，无需加密）；job 登记联动：简报 job 受任务级开关 `briefing_on`（job.template.json `enabled_field`，关闭即注销）与 phase 级 `planner_on` 双重 AND 判定。job 使用 bridge 的 `web_search`、`fetch_url`、`write_file`，产物声明为 `{date}.html`；基底 prompt、方向声明或自定义方向变化会使旧执行失效并重新登记。
- 清理策略：简报数 > 5 → 每 5 天清最旧 5 个；≤ 5 → 清 3 天前；≤ 3 → 不清理

## 边界

- 逾期推送只在此模块（todo 模块不管逾期）
- 任务数据缺失（todo 未运行/未装）→ 待办/逾期/完成段自动无段，不报错
- 简报文件缺失 → 走未就绪兜底（见晨间早报节）：任务已登记等 retry 超次保底，未登记/诊断异常标注照发
- 话术风格跟随全局人设（部署态 instructions 指引）；本模块 agents.md 只写素材组织规则，不独立定制话术
