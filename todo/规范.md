# todo 模块 · 规范

> 职责：待办提醒——每分钟扫描数据源，对"今天到期且到点未推"的待办按触发时刻分组合并推送；并刷新共享层 `shared/tasks.json` 供其他模块/agent 查询。
> 调度：bridge 按 `modules/todo/module.json` 的 schedule（every 1m）spawn（**单一事实源，以 module.json 为准**），跑完即止。

## 数据源（单数据源，设置切换，不迁移）

- `settings.data_source = internal`（默认）：模块自管 `modules/modules_data/todo/tasks/YYYY-MM.json`（agent 维护，操作指引见 agents.md）
- `settings.data_source = vault`：**递归**扫描 `vault_path` 下所有 `.md`（`**/*.md`，排除 `.` 开头隐藏文件）的 Tasks 任务行（复用 common/task.py 解析器）；**带日期标注（📅）的才算待办**；⏰ 时间标记为本产品扩展（Tasks 原生无时间字段）；写入位置 = `settings.vault_task_dir`（绝对路径，留空默认 `vault_path/cabclaw-todo/`），文件固定 `todo-YYYY-MM.md`（当月存在则追加）

## 任务 schema（共享层与 internal 权威文件一致）

```json
{
  "id": "8位hash",           // 防重键基础（日期|id）；vault 由 sha1(due|text) 稳定生成
  "text": "任务正文（人话）",
  "due": "2026-08-19",       // 到期日期 YYYY-MM-DD
  "time": "14:30",           // 到期时刻 HH:MM（无 = 不进提醒，仅共享层供查询）
  "start_time": null,        // 可选：用户明确给出的独立开始时刻，绝非 time/reminder_time
  "start_date": null,        // 可选：明确开始日期；无则不猜日期
  "remind_min": 15,          // 提前量分钟（null=无）
  "done": false,             // 单次任务完成状态
  "done_at": null,           // 完成时刻 ISO "YYYY-MM-DDTHH:MM:SS"（Planner 晚报据此判断"今日完成了什么"；旧数据/vault 仅日期粒度）
  "repeat": null,            // 可选：{"freq":"daily|weekly|monthly","interval":1,"until":"2026-08-31"}
  "done_dates": [],          // 重复任务按天完成记录（YYYY-MM-DD 列表）
  "tags": ["工作"]           // 词表白名单（settings.tags_vocab）
}
```

## 文件组织（internal）

- `tasks/YYYY-MM.json`：agent 按任务**实际执行月**（due 月份）写，不存在则新建，原子写回
- 文件形态：`{"month": "YYYY-MM", "tasks": [...]}`（兼容裸数组）
- worker **全扫所有** `tasks/*.json` 按 due 过滤（防跨月漏：上月/上上月逾期也在扫描内，不误事）

## 判定与推送

- 提醒日判定（加载时算好存 `reminder_date`/`reminder_time` 字段）：`remind_min ≤ time 分钟数` → 提醒日 = 到期日；**跨日（remind_min > time 分钟数）→ 提醒日 = 到期日前一天**（如 00:30 到期提前 60 分钟 → 前一日 23:30 提醒）
- 扫描：`reminder_date == 今天` 且 `reminder_time` 已到 → 提醒（无 offset 分支，worker 不查到期日）
- 今日已完成的跳过（单次 `!done` / 重复 `today ∉ done_dates`）
- vault 模式重复任务（行内 🔁）：**仅标记，worker 不展开 repeat**——重复提醒依赖 Obsidian Tasks 插件生成新任务行（每行独立 due/time）
- 推送：同一触发时刻最多 6 项合并一条；`type=reminder` 的 `facts.tasks` 逐项携带原文、到期日期/时间、提前量、触发日期/时刻和可选独立开始时刻。`event_id` 由提醒日、时刻与任务 ID 组生成；主体仅据这些事实按人设表达，不猜开始/结束，不直发清单素材。
- 防重：先原子写 `todo_pending.json` 保存稳定事件键、事实及任务关联；丢失 POST 200 回执先查宿主状态，仅 404 可重投原键原事实；`sent` 后才写 `todo_sent.json` 的 `提醒日|id`，`failed/unknown` 不换键自动补发。终态 pending 保留 30 天，未决记录保持待查询。
- 无 time 任务：不入提醒（避免全天任务深夜打扰），仅进共享层供查询

## 失败语义

- 网络/鉴权不可用 → rc=1；HTTP 200 仅持久接受不记已发。下个 1 分钟 tick 查询 `queued/rendering/sending/sent/failed/unknown`，失败或不确定结果保留明确记录，不冒充客户端已收到，也不更换业务键重试。
- `--dry-run`：只打印扫描/待提醒摘要，**零副作用**（不推送/不写 sent/不刷 shared/不 prune）
- worker 读容错：坏 JSON 跳过该文件 + WARN 告警，绝不崩循环

## 共享层

- `modules/common/shared/tasks.json = {ts, tasks:[全量]}`，唯一写者 = todo worker；**tasks 内容变了才写**（深比较，无变化跳过，避免每分钟无用全量 I/O）
- vault 模式加载走**增量**（`scan_cache.json` 按文件 mtime 缓存解析结果，只重解析变化的 .md；缓存坏全量重扫）
- 消费方请带 `max_age=600` 校验新鲜度（过期返回 {} 降级，君子协定）；agent 查询走共享层，不翻模块内部文件
- agent 改任务只能改权威文件（internal=tasks/*.json / vault=vault_task_dir 指定位置，留空默认 vault_path/cabclaw-todo/），不直接改 shared；vault 模式误写 internal 由 worker 检测告警（WARN + 一次性 notification）

## 标签

- 词表 `settings.tags_vocab`（可编辑，默认 工作/学习/生活/家庭/购物/健康/娱乐）；`allow_new_tag=false` 时 agent 不得自造新词
- vault 读取：`extract_tags` 开 + `tag_prefix`（含 # 的前缀，如 "#todo/"）→ 只提取"前缀+词"命中词表的进 tags；**前缀留空 = 不提取**（无前缀标签无法可靠区分，不加）
- vault 写回：agent 按用户既有前缀写（如 `#todo/工作`），跟随用户习惯（兼容不吞并）
